---
title: Worktrees
description: Work on several branches of one repo at once, where each worktree is its own workspace.
---

Git worktrees let one repository have several branches checked out in separate
folders. luvus makes them **first-class workspaces**. Creation uses the built-in
Git provider by default, so existing installations keep their current behavior.
You can opt into Worktrunk for creation while removal and task merge continue to
use Git directly.

## Creation provider

Set the provider in `~/.luvus/config.json` (debug builds:
`~/.luvus-dev/config.json`):

```json
{
  "worktree": {
    "provider": "worktrunk",
    "executable": "wt",
    "args": ["--no-hooks"]
  }
}
```

`executable` is one executable name or path, not a shell command. `args` is a
JSON argv array; Luvus never passes it through a shell. Luvus owns and protects
Worktrunk's repository, operation, branch, navigation, and output arguments:
`-C <repo> switch [--create] <branch> --no-cd --format json`. `--create` is
included only when the requested local branch does not exist.

Conflicting or contract-changing arguments are rejected, including `-C`,
`--config`, `--config-set`, `--format`, `-x`/`--execute`, `--cd`/`--no-cd`,
`-c`/`--create`, `-b`/`--base`, branch-picker options, `--clobber`, `--`, and
`-y`/`--yes`. The last restriction is intentional: Luvus does not approve or
skip Worktrunk project hooks. If Worktrunk reports that hook approval is needed,
review and approve it interactively with Worktrunk, then retry.

Worktrunk chooses the worktree path. Before opening it, Luvus verifies that the
path exists, is a registered worktree of the source repository, shares its Git
common directory, and has the requested branch checked out. Worktrunk's JSON is
read from stdout; human logs and actionable hook errors on stderr remain intact.

## Create one

- **`Ctrl+Space G`**: type a branch name. With the default provider, luvus runs
  `git worktree add` under `~/.luvus/worktrees/<repo>/<branch>` and opens it as a
  workspace. With Worktrunk, `wt switch` chooses the path from your Worktrunk
  configuration. `esc` or a click outside the prompt cancels it.
- **The folder picker** (`Ctrl+Space N`): when browsing a git repo, an *Open
  with new worktree* row (or the `w` key) does the same for that repo.
- **CLI**: `luvus worktree create <branch>` · `open <path>` · `list` ·
  `remove <path>` (the branch is kept).

## Open one

Right-click a repo's sidebar row and choose **Open Worktree**. The list is fed
by `git worktree list`, so it shows every existing, non-bare checkout git knows
about, wherever it lives on disk and whichever tool created it: a sibling folder from
`git worktree add ../feature`, one made by another editor, or one under
`~/.luvus/worktrees/`. Each row shows the branch (or the short commit when
detached), the path, and an **open** badge when that checkout is already a
workspace.

- `⏎` opens the highlighted checkout as a new workspace. If it is already open,
  luvus **focuses that workspace** instead of opening a duplicate, since a
  worktree is one place.
- `↑`/`↓` (or `j`/`k`) move, `esc` closes. Rows are clickable.
- The listing runs off the app loop, so a slow filesystem shows a brief
  *Loading worktrees…* row rather than stalling the terminal.

Bare entries and worktrees whose folder is already gone (`git worktree prune`
would remove them) are left out, since there is nothing to open.

## Why it's great with agents

Each agent works in its own worktree, with its own files on disk, so two agents
can work the same repo without any chance of stepping on each other's edits.
The sidebar **nests worktrees under their repo**, so the grouping is always
visible. This is also the foundation the
[orchestration board](/docs/guides/orchestration/) builds on.
